# aiden估值助手

## 1. 工作目录与唯一真相源

- 技能根目录：本 `SKILL.md` 所在目录。模型代码、配置、测试、数据和报告规范均已随技能包提供。
- **本地文件夹为唯一真相源，不使用 GitHub，不进行 git push/pull。** 不下载参考仓库，不依赖远程提交、外部账户或网络信息接续工作。
- 所有模型路径必须相对于技能根目录定位，或由 `config_loader.py` 推导；不得把制作者电脑上的绝对路径写入实现代码。
- 所有命令默认在技能根目录执行；模型假设只从 `config/aircraft.yaml` 进入，航司信用输入使用本地 `data/airline_credit_inputs.csv`。

## 2. 每次任务开始前的固定流程

严格按顺序执行：

1. 完整阅读 `MODEL_SPEC.md`，重点核对 §2 配置、§3 模块规格、§4 校验基准、§6 特别声明。
2. 首次使用或依赖环境不完整时，在技能根目录运行 `python scripts/setup.py`。脚本只在技能目录内创建 `.venv`、安装 `requirements.txt` 并运行全量测试；不修改系统 Python，不依赖 GitHub。Python 未安装或依赖下载失败时，明确报告，不得宣称安装完成。
3. 环境就绪后运行 `.venv` 中的 `python -m pytest -q`。当前基线为 **37 passed**；若失败，立即停止修改并报告失败测试、错误摘要和初步根因。后续新增测试时，以最近一次全量通过结果更新基线，不得为维持数量而删除测试。
4. 确认任务所属模块和允许修改的文件，阅读对应实现与测试。跨模块改动必须先说明数据流和必要性，不得借当前任务重写无关模块。

## 3. 模块边界

| 文件 | 职责边界 |
|---|---|
| `src/engine_residual.py` | 残值估值：出厂机龄锚点、发动机维护状态、逐月三情景残值曲线；不计算租赁 IRR 或 DCF 分拆 |
| `src/lease_returns.py` | 租赁收益：租金、债务摊还、CFADS、DSCR、Equity IRR、MOIC、租金警告与收益仪表盘；不重新定义残值或部件估值 |
| `src/asset_valuation.py` | 分部件估值：整机无杠杆 DCF、机体/发动机分摊、维护调整、隐含折现率与敏感性；不修改收益口径 |
| `src/airline_credit.py` | 航司信用：复算本地分项数据、校验锚点、映射信用调整后的 LTV/LRF 并输出信用报告；不另建租赁规则 |
| `config/aircraft.yaml` | 唯一假设入口：资产、发动机、租约、债务、残值、WACC、情景和信用参数；不得用代码常量替代配置假设 |

配置结构与加载校验由 `src/config_loader.py` 负责。新增配置字段时同步更新类型定义、校验、配置和测试，不绕过 `load_config()`。

## 4. 硬性约束

- 禁止在模型实现中硬编码绝对路径；输入统一走 `config_loader.load_config()`，输出写入配置的 `output.dir`。
- 禁止调参凑数。校验不过时先检查实现，再检查业务口径；参数或口径变更必须给出证据和理由，不得为通过测试反向修改假设。
- 任一适用校验不通过，停止并回滚该任务的改动，不影响其他模块，不提交失败状态。完整校验口径见 MODEL_SPEC §4。
- Equity IRR 的 10%–20% 仅为参考区间，不是硬门槛；超出时解释 CMV 偏离、隐含折现率与 WACC 差异，不据此判定失败或调参。
- `engine_premium_switch` 默认关闭；不得把特殊行情内化为默认残值。见 MODEL_SPEC §6.3。
- 残值公开数据只支持区间级校准，输出须保留来源与可信度，见 MODEL_SPEC §6.1。
- 保留 LRF、定价基数与月租金的联动校验；偏离合理区间时明确警告，见 MODEL_SPEC §6.2。
- 修改测试断言必须先说明原断言、业务口径变化及修改理由；不得删除、放宽或改写断言来掩盖实现错误。
- 保持现有中文 docstring、类型注解和模块风格；只修改任务所需文件。

## 5. 执行与完成流程

1. 先写能复现需求或缺陷的测试，再实现最小改动；运行相关测试后运行全量 `python -m pytest -q`。
2. 需要报告时运行对应模块入口，检查 `outputs/` 中文件确实生成；报告数值必须来自实际运行，不得手工编造。
3. 对照 MODEL_SPEC §4 逐项检查适用校验。存在未通过项时按第 4 节回滚并报告，不本地提交。
4. 全部通过后创建本地 commit；提交信息概括实际改动。**只允许本地 commit，禁止 push/pull。**

任务完成后的回复固定按以下顺序：

1. **改动说明**：列出文件、行为变化和必要口径说明。
2. **pytest 结果**：贴出实际全量结果和通过数。
3. **关键结果表**：按任务列示三情景 IRR/MOIC/Min DSCR、部件估值、残值锚点、信用评分或敏感性结果；不适用时明确写“不适用”。
4. **未通过项的根因与建议**：无未通过项时写“无”；有则列根因、影响和建议，且不得宣称任务已完成。
5. **本地 commit**：给出提交哈希与提交信息，并明确“未 push”。

## 6. 常用任务模板

### 6.1 运行完整测算

依次运行：

```bash
python src/engine_residual.py
python src/lease_returns.py
python src/asset_valuation.py
python src/airline_credit.py
python -m pytest -q
```

核对残值曲线、三情景收益、整机与部件估值、敏感性矩阵和五家航司信用报告；按第 5 节固定格式汇总，不修改假设。

### 6.2 换机型

1. 列出机龄、购机价、CMV、利用率、发动机数量、LLP、维修成本、租约和残值锚点等待换参数及来源。
2. 只通过 `config/aircraft.yaml` 修改假设；如需新增字段，同步扩展 `config_loader.py`。
3. 检查机型专用租金警告、测试中的机龄基准和残值锚点是否仍适用；修改断言须说明理由。
4. 运行完整测算和全量测试，比较换机型前后的关键结果，不通过则回滚本任务。

### 6.3 加情景

1. 在 `config/aircraft.yaml` 的 `scenarios` 中增加情景，明确 `fuel_pct`、`demand_pct`、`margin_comp` 的业务含义。
2. 确认残值、收益和估值接口的情景取数是否符合任务要求；估值默认仍使用 base，除非用户明确要求改变。
3. 扩展报告与 Dashboard 的动态行数和图表范围，补充情景排序、现金流和输出测试。
4. 运行全量测试并展示新增情景与 base 的对比，不用调整既有参数消除差异。

### 6.4 敏感性分析

1. 默认使用 MODEL_SPEC §3 的 WACC ±200bp、LRF ±25bp；扩展范围时单独列示，不覆盖基准矩阵。
2. 由 `src/asset_valuation.py` 统一计算，保持租金、期末残值和维护调整口径一致。
3. 至少验证 WACC 上升导致估值下降、LRF 上升导致估值上升，并报告矩阵和单位。
4. 敏感性结果仅用于分析，不据此反推或调优基准假设。

### 6.5 独立估值与 Word 报告

1. 优先回答当前裸机值多少钱、带租约最高可承受买价、租约到期残值和什么价格算买贵。
2. 独立形成估值，不以内部材料中的价格、账面值或残值作为锚点；裸机市场价值与带租约 DCF 分开列示且不得相加，MR 未拆分或未明确归属时必须做敏感性。
3. 用户要求正式估值结论、估值报告或 Word 时，完整阅读并执行 [独立估值 Word 报告规范](references/independent-valuation-word-report.md)，生成实际 `.docx` 并在对话框交付。
4. 报告固定包含核心结论、当前裸机价值、带租约 DCF、MR 风险、到期残值、价格纪律、估值边界和外部来源脚注；所有数值来自实际模型运行或可追溯计算。
5. 交付前校验文档结构、关键数值勾稽和文件完整性；视觉预览不可用时明确说明，不宣称已完成视觉检查。
