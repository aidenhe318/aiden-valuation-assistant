# 独立估值 Word 报告规范

正式交付发动机独立估值结论时，按本规范生成 `.docx`。快速问答可先给文本结论；用户要求“写成报告”“做成 Word”“把结论发到对话框”时，必须生成并交付实际文件。

## 一、报告必须回答的问题

1. **现在值多少钱**：给出当前裸机市场价值区间、中枢、估值日期和关键条件，直接服务于“是否买贵”的判断。
2. **带租约买多少钱合理**：若资产附带租约，用现金流折现给出可承受买价，并列明租金、MR、费用、税、折现率、初始费用和期末残值假设。
3. **租约到期值多少钱**：给出预计交机时点的残值区间、中枢、技术状态条件及下行情形。
4. **什么价格算贵**：列出不同买价的 NPV 或价值差额，给出可执行的价格纪律，不只给抽象估值区间。

## 二、估值表达纪律

- 结论必须独立形成。内部材料仅用于资产身份、技术状态、租约和税费等客观输入；不得采用其中的拟成交价、账面值、内部评估值、关联方回购价或内部残值作为估值锚。
- 将**裸机市场价值**与**带租约整体价值**分开。带租约 DCF 已包含租金及期末残值，不得再与裸机价值相加。
- 当前价值以外部市场基准为起点，说明机型、推力等级、剩余循环、LLP、维修状态、文件完整性和市场周期调整。状态调整须标为估值判断，不伪装成第三方正式评估。
- 带租约价值采用口径一致的无杠杆税后 DCF。折现率反映单台资产、承租人、MR、技术资料及退出流动性风险，不直接以融资利率或内部目标收益率替代。
- 固定租金与 MR 必须拆分。MR 可用性、返还义务、维修报销义务或交机状态不明时，至少测试 0%／50%／100%可用比例；演示拆分不得写成合同事实。
- 残值必须对应预计交机循环、LLP、性能恢复、维修记录、退租条件和市场正常化风险。区间下限不是绝对保底；重大维修或不利交机状态可突破下限。
- 资料不足时明确“独立桌面估值”的性质、待核资料和结论适用边界，不冒充 ISTAT、IBA 或其他持证评估。

## 三、固定结构

### 封面

- 标题：`aiden 独立估值`＋资产编号／发动机型号。
- 副标题：当前价值、带租约 DCF、租约到期残值。
- 估值日期、计价货币。
- 三行核心结果表：当前裸机、带租约收购价值、到期残值；每行包含区间或情景及中枢／基准。
- 一段价格纪律和一条醒目口径提示：带租约价值不得与裸机价值相加。

### 目录

提供可见目录及页码，并提示在 Word／WPS 中更新域。不得只插入打开后一片空白的目录域。

### 一、核心估值结论

先用一段给出谈判所需的三个数字，再用表格列示估值对象、独立结论和适用条件。若相较上一版调整区间，说明方法或证据变化，不只宣布新数字。

### 二、当前裸机市场价值

- 外部基准及估值时点。
- 本机技术状态与资料完整性调整。
- 区间、中枢及调整逻辑。
- “价格含义”项目列表：合理区间上部、需要额外证据的价格、缺乏支持的价格。

### 三、带租约 DCF 估值

- 现金流范围、税务口径、折现率和关键假设。
- 折现率 × 残值的最高合理买价矩阵。
- 不同买价的 NPV 表，并给出“有安全边际／接近全价／买贵／缺乏支持”等直接判断。
- 所有表格标注单位；正文明确结果不得与裸机价值重复相加。

### 四、MR 与合同条款风险

- 区分固定租金和 MR，说明 MR 的经济实质。
- 列示 MR 可用比例与合理买价敏感性。
- 给出签约前核查清单：租金拆分、支付频率、MR 归属、偿债可用性、返还义务、维修报销、退租循环、LLP、性能恢复、文件与适航状态。

### 五、租约到期残值

- 外部可比区间与本机残值区间、中枢。
- 预计交机技术状态和市场周期假设。
- 下行情形及需要滚动更新的变量。

### 六、买贵判断与价格纪律

用表格或项目列表给出买价分档：优先谈判区、接近全价区、基准下买贵区、缺乏支持区。结论必须能直接用于报价和谈判。

### 七、估值边界与后续工作

列出仍需核验的技术包、合同和税务事项，以及这些事项对估值的潜在影响。区分已核实事实、估值假设和敏感性演示。

### 数据来源

外部市场与技术证据使用 Word 原生脚注，写明机构、资料标题、发布日期或访问日期、URL。不得虚构来源；未核实内容标为“未核实”。

## 四、版式与语言

- 使用正式、简洁的中文，先结论后依据，避免宣传性措辞和空泛风险描述。
- 封面、页眉页脚、页码、可见目录、统一标题层级、固定列宽表格和原生脚注齐全。
- 数值统一币种和单位；万美元表格不得混用美元原值。区间、中枢、基准和压力情景清楚区分。
- 每页只承担一个主要论证任务，避免跨页断表、孤立标题和大面积空白。

## 五、交付前检查

1. 所有数值来自实际模型运行或可追溯计算，关键结果与 Excel／模型输出一致。
2. 检查裸机与带租约口径、MR 假设、折现率、残值和 NPV 的勾稽关系。
3. 使用文档工具完成 DOCX 结构与语义校验，确认文件实际存在、非空、ZIP 完整且正文和脚注部件存在。
4. 可行时渲染检查封面、目录、表格分页、脚注和空白页；视觉检查不可用时明确说明，不因此重复安装环境或宣称已完成视觉检查。
5. 在对话框交付最终 `.docx` 文件，不把生成脚本或中间文件当成报告交付。
